# 11/21 完成记录

> 本轮修 B站链接兼容：`/id/video/` 路径和 App 分享文案。

## 一、问题

用户给的两类链接都下载不了：

1. 带 `/id/` 的路径：

```
https://www.bilibili.com/id/video/BV1AsWw6MEKa/?p=5&vd_source=...
```

yt-dlp 把它当成普通网页，走 generic 解析，返回：

- `platform=generic`
- `formats=[]`

2. App 分享文案：

```
【【2026精选】10月Java面试…】https://www.bilibili.com/video/BV1AsWw6MEKa?p=63&vd_source=...
```

前端输入框是 `type="url"`，浏览器原生校验直接拦下，点解析没反应。

## 二、后端修复

新增 `security.extract_share_url()` 和 `normalize_video_url()`：

- 从任意分享文案里提取第一个 `http(s)` 链接
- B站 `/id/video/BV...` → `/video/BV...`
- 只保留 `p` 参数，去掉 `vd_source`、`spm_id_from` 等跟踪参数
- 没有链接时返回 400：「没有识别到视频链接，请粘贴完整分享内容」

`_prepare_url()` 统一做「提取 → SSRF 校验 → 归一化」，接入：

- `/api/parse`
- `/api/download`
- `/api/download/start`
- `/api/direct-url`
- `/api/summarize`
- `/api/chat`

## 三、前端修复

`HeroSection.vue`：

- 表单加 `novalidate`，不再被 `type="url"` 原生校验拦截
- 提交时从分享文案提取链接，并回填到输入框
- 用户看到的是干净 URL，后端也能正常解析

## 四、实测

### `/id/video/` + `p=5`

- 平台：`BiliBili`
- 标题：`…p05 JVM专题-05、你知道哪些垃圾收集算法`
- 时长：6:14
- 5 档格式
- 1080p 合并下载 18,642,982 B

### 分享文案 + `p=63`

- 文案提取成功，输入框回填为纯 URL
- 标题：`…p63 微服务面试`
- 时长：8:14，5 档格式
- 360p 下载：4,579,386 B
- H.264 640×360，全片解码退出码 0

### 异常

- 文案里没有链接：400 + 中文提示
- 标准 `https://www.bilibili.com/video/BV...?p=5` 仍正常
