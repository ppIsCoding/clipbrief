# 11/20 完成记录

> 本轮处理“下载后打不开”的排查，并顺手把下载方式、AI 错误提示和 JWT 默认配置收尾。

## 一、`chrome://downloads` 里“打不开”的原因

排查发现，出问题的条目都是这种样子：

- 文件名是一串 UUID（如 `4c58b79b-f1e7-...`）
- 状态显示「已删除」
- 点「在文件夹中显示」找不到文件

这些是 **Playwright 自动化测试产生的临时下载**：Playwright 会把下载文件接管到临时目录，测试结束后删除；浏览器下载记录里就留下 UUID 名和「已删除」。

它们不是应用真实下载的文件。实际文件在仓库根目录 `.playwright-mcp/`，例如：

```
.playwright-mcp/【官方-MV】Never-Gonna-Give-You-Up---Rick-Astley.mp4
```

验证结果：

- 大小 75,234,063 字节
- H.264 1920×1080 + AAC
- Windows 资源管理器可读出时长 00:03:32
- ffmpeg 全片解码退出码 0

结论：文件本身能播；之前看到的 UUID 条目是测试残留。

## 二、下载方式改为直链

原来前端用 axios 取 blob，再用 `<a download>` 保存。问题：

- 75 MB 全量进浏览器内存
- 需要手动解析 `Content-Disposition` 文件名
- 需要延迟回收 blob URL，否则部分浏览器会取消下载

现在改成：SSE 收到 `done` 后，直接跳转到 `/api/download/file/{task_id}`：

- 浏览器原生下载，文件名由服务端 `Content-Disposition` 给出
- 不占 JS 内存，不需要 blob 回收
- `chrome://downloads` 里显示真实文件名

实测 360p：

- 文件 9,292,223 字节
- H.264 640×360，时长 212.26 秒
- 全片解码退出码 0
- 页面没有跳走，仍停留在解析结果

## 三、AI 错误提示

- 缺少 Key：返回「AI 总结服务未配置（缺少 API Key）」
- 鉴权失败：返回「AI 服务鉴权失败，请检查 API Key 配置」
- 限流：返回「AI 服务额度不足或请求过于频繁，请稍后重试」
- 连接超时：返回「AI 服务连接超时，请稍后重试」
- 其他异常：保留前 200 字符，方便排查

总结和问答两个 SSE 接口都走这套映射。

## 四、JWT 默认值

- 默认密钥改为 33 字节以上，PyJWT 不再报 `InsecureKeyLengthWarning`
- `.env.example` 的 `JWT_EXPIRE_HOURS` 从 24 改为 72，与代码和接口文档一致

## 六、自查方式

1. 用你自己的 Chrome/Edge 打开 `http://localhost:5173`（不是自动化窗口）。
2. 下载后去浏览器设置的下载目录找，Chrome 当前是 `E:\Download`。
3. 文件名应是中文标题，不是 UUID。
4. 打不开时优先用 VLC / PotPlayer 试，排除系统播放器关联问题。
